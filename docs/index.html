Compaction under the hood: rewrite_data_files (bin-pack)

target-file-size-bytes
Size of each OUTPUT file. Iceberg default: the table’s write target (512 MB).
max-file-group-size-bytes
Max INPUT per rewrite group (one unit of work). Default: 100 GB.
max-concurrent-file-group-rewrites
Groups rewritten at the same time. More = faster, more compute. Default: 5.
partial-progress.enabled
Off (default): one commit at the very end.
partial-progress.max-commits
Upper limit on commits. Only used when partial progress is on. Default: 10.

Candidates are files smaller than 75% of the target size (Iceberg’s default min-file-size-bytes). Groups never mix partitions. Readers on the old snapshot keep working while the rewrite runs; new readers see the compacted layout after the commit.

Automate it: maintenance policy

off

Turn this on, then tick “Keep streaming”. Instead of compacting by hand, the policy watches the table’s state (or the clock) and runs maintenance for you: the idea behind managed table optimizers.
